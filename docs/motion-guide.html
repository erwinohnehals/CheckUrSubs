Implementation rules

Overlap, do not replace

Stack panes absolutely. Keep the old pane visible until its exit ends; start the new one at 150 ms. Replacing DOM immediately removes the cross-slide.

Stagger meaningful groups

Tag cards or sections, not every child. Animate them for 350 ms with an 80 ms step and cap the delay index so long lists do not become slow.

Use one physical pill

Measure the active button and translate one pill element. Snap on first paint; animate later moves. On a section rebuild, remount and fade the new pill.

Keep it interruptible

Clear the previous animation, force one layout read for the whole batch, then apply every stagger. Prefer a cleanup timer over relying only on animationend.

Promote briefly

Set will-change: transform, opacity only while a cascade is running, then clear it. The tiny pill can remain promoted because it moves frequently.

Respect reduced motion

Collapse animation and transition durations under prefers-reduced-motion, and remove the outgoing pane immediately in application code.

Copy-ready core

const motion = {
  standard: 'cubic-bezier(.625,.05,0,1)',
  power1Out: 'cubic-bezier(.25,.46,.45,.94)',
  power1In: 'cubic-bezier(.55,.085,.68,.53)',
  view: 250,
  incomingDelay: 150,
  groupDuration: 350,
  groupStep: 80,
  pill: 400,
};

// At t=0: animate old pane out and start moving the tab pill.
oldPane.style.animation = `view-out 250ms ${motion.power1In} forwards`;
// At t=150: animate the new pane and its meaningful groups in.
newPane.style.animation = `view-in 250ms ${motion.power1Out} 150ms backwards`;
groups.forEach((group, i) => {
  const delay = 150 + Math.min(i, 24) * 80;
  group.style.animation = `rise-in 350ms ${motion.standard} ${delay}ms backwards`;
});
// Remove oldPane after 250ms (+ a small scheduling buffer).
